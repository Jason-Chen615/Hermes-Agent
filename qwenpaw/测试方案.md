# QwenPaw SCCS Bench 测试方案

本方案用于对 QwenPaw 的**工具结果压缩**做 A/B 基准测试。测的是 **token/延迟/压缩等性能指标**，
不做正确性判断。仅覆盖 **test1 / test2**（kubernetes 相关用例）。

## 一、核心思路

同一个用例跑两次，**只切「工具结果压缩」这一个变量**，其余配置保持一致，再用 `compare` 对比。

### 隔离方案（4-agent 设计）

**记忆按 `agent_id` 绑定**，同一 agent 的所有 session 共享一套记忆库。为避免跨测试样例、跨配置的记忆污染，采用 **每个「测试样例 × 配置」= 一个独立 agent** 的设计：

| agent-id | 测试样例 | 工具压缩开关 |
| --- | --- | --- |
| `sccs-t1-base` | test1 | 关（baseline）|
| `sccs-t1-cand` | test1 | 开（candidate）|
| `sccs-t2-base` | test2 | 关 |
| `sccs-t2-cand` | test2 | 开 |

**优点:** 记忆天然隔离；配置固化进各自 agent.json，跑时无需改配置+重启；4 个可并行跑。

### 变量定义

- **baseline（base）**：`tool_result_pruning_config.enabled = false`
- **candidate（cand）**：`tool_result_pruning_config.enabled = true`
- 其余配置（`context_compact_config`、`summarize_when_compact` 等）**4 个 agent 保持一致**，避免混淆变量。

### agent.json 配置路径（每个 agent 各自配）

agent.json 位置：`<WORKING_DIR>/workspaces/<agent-id>/agent.json`

| 配置项 | 完整路径 | `*-base` agent 设为 | `*-cand` agent 设为 |
| --- | --- | --- | --- |
| 工具结果裁剪 | `running.light_context_config.tool_result_pruning_config.enabled` | `false` | `true` |
| 上下文压缩 | `running.light_context_config.context_compact_config.enabled` | `true` | `true` |
| 记忆摘要沉淀 | `running.reme_light_memory_config.summarize_when_compact` | `true` | `true` |

> 改完 agent.json 需**重启 qwenpaw 容器**（配置在启动时加载）。

## 二、执行步骤

### 前置：创建 4 个隔离 agent

```bash
qwenpaw agents create --name "sccs-t1-base" --agent-id sccs-t1-base
qwenpaw agents create --name "sccs-t1-cand" --agent-id sccs-t1-cand
qwenpaw agents create --name "sccs-t2-base" --agent-id sccs-t2-base
qwenpaw agents create --name "sccs-t2-cand" --agent-id sccs-t2-cand

# 验证
qwenpaw agents list
```

创建后，按上面「agent.json 配置路径」表格，分别配置每个 agent 的 agent.json，然后重启 qwenpaw 容器。

### 运行测试（配置固化，无需中途改配置）

每个用例（test1、test2）各跑 baseline + candidate + compare 一轮。

> **QwenPaw 跑在 docker 容器里**，记忆目录位于容器数据卷（`qwenpaw-data → /app/working`），
> host 上不能直接删，所以 reset 用 **docker 模式**（`--docker qwenpaw`），
> 由脚本 `docker exec` 进容器删。容器名按实际填（下面示例为 `qwenpaw`）。

```bash
# ── test1 baseline ──
python reset_memory.py --agent sccs-t1-base --docker qwenpaw
python run_sccs_bench.py run --prompts test1.json --label test1-base \
  --session-id "bench-$(date +%s)-t1b" \
  --out-dir bench-results/t1-base --agent sccs-t1-base

# ── test1 candidate ──
python reset_memory.py --agent sccs-t1-cand --docker qwenpaw
python run_sccs_bench.py run --prompts test1.json --label test1-cand \
  --session-id "bench-$(date +%s)-t1c" \
  --out-dir bench-results/t1-cand --agent sccs-t1-cand

# ── test1 compare ──
python run_sccs_bench.py compare \
  --baseline  bench-results/t1-base/test1-base-<stamp>.json \
  --candidate bench-results/t1-cand/test1-cand-<stamp>.json

# ── test2 同理 ──
python reset_memory.py --agent sccs-t2-base --docker qwenpaw
python run_sccs_bench.py run --prompts test2.json --label test2-base \
  --session-id "bench-$(date +%s)-t2b" \
  --out-dir bench-results/t2-base --agent sccs-t2-base

python reset_memory.py --agent sccs-t2-cand --docker qwenpaw
python run_sccs_bench.py run --prompts test2.json --label test2-cand \
  --session-id "bench-$(date +%s)-t2c" \
  --out-dir bench-results/t2-cand --agent sccs-t2-cand

python run_sccs_bench.py compare \
  --baseline  bench-results/t2-base/test2-base-<stamp>.json \
  --candidate bench-results/t2-cand/test2-cand-<stamp>.json
```

总计 4 次 run（test1×2 + test2×2）+ 2 次 compare。4 个 agent 独立，可并行跑。

> 加 `--dry-run` 可先看会删哪些目录、不真删；确认无误再去掉重跑。
> 若 host 能直接访问数据卷（root），也可用 host 模式：
> `python reset_memory.py --agent sccs-t1-base --working-dir /var/lib/docker/volumes/qwenpaw-data/_data`

### 记忆隔离与删除粒度

- **记忆按 agent_id 绑定**：每个「样例 × 配置」用独立 agent，记忆互不污染。
- **reset 只在每次（重）跑前执行一次**；**轮之间不 reset**（test 内 3 轮要共享 context/记忆，第 3 轮依赖前两轮上下文）。
- 4 个 agent 记忆独立，reset 只清对应 agent，其余不受影响。
- **docker 模式 reset**：`reset_memory.py --agent <id> --docker <容器名>`，脚本 `docker exec`
  进容器删 `/app/working/workspaces/<id>/` 下的记忆子目录（`memory/ digest/ mem_metadata/
  mem_session/ mem_agent/ resource/`）。默认容器内 WORKING_DIR 为 `/app/working`，
  与实际不符时用 `--container-working-dir` 覆盖。删除只限该 agent workspace 之内。

## 三、产出物

| 命令 | 产出文件 | 内容 |
| --- | --- | --- |
| `run` | `<label>-<stamp>.json` | 完整报告：metadata + summary + 逐轮 rows |
| `run` | `<label>-<stamp>.csv` | 逐轮指标表（Excel 可直接打开）|
| `compare` | `compare-<ts>.json` | 两份报告的指标差值 + 百分比 |

每次 `run` 还会在终端实时打印每轮的 `durationMs / totalTokens` 与最终 totals。

## 五、备注

- **SCCS 是原 bench 起的标签名，非产品功能名**；真正做压缩的是 QwenPaw 原生的
  `tool_result_pruning_config`（+ `context_compact_config`）。
- **只切 `tool_result_pruning_config.enabled` 一个变量**，其余配置 4 个 agent 保持一致，
  compare 的 token 差值才归因清晰。
- **4-agent 设计原因**：记忆按 `agent_id` 绑定（`ReMeLightMemoryManager(working_dir, agent_id)`），
  同一 agent 的所有 session 共享一套记忆库；采用独立 agent 避免跨测试样例、跨配置的记忆污染。
- **记忆写入触发**：轮次累积（`auto_memory_interval`，默认 5）或上下文压缩时
  （`summarize_when_compact=true` 且 context token 占比 ≥ `compact_threshold_ratio`，默认 0.8）
  都会触发记忆写入。3 轮的 test 在默认配置下，记忆写入取决于是否触发了上下文压缩。
