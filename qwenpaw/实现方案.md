# toolresult 压缩 bench 迁移实现方案：OpenClaw+OpenViking → QwenPaw 原生记忆

## 1. 背景与目标

现有 bench（`../run-sccs-bench.mjs`）是 Node 脚本，反复以子进程方式调用
`openclaw agent --json` 跑多轮 prompt，测量 **OpenClaw + OpenViking** 工具结果
压缩链路的 token / 延迟 / compaction 指标。

本次迁移目标：

- **Agent**：OpenClaw → **QwenPaw**
- **记忆系统**：OpenViking → **QwenPaw 原生 ReMe Light**（向量 + BM25 混合检索）
- **脚本语言**：Node(mjs) → **Python**
- 保持原有能力：多轮 prompt 回归 + 逐轮 token/上下文指标 + 用例间干净重置记忆
- **路径环境自适应**：Windows 编辑、Linux 部署都不改用例文件
- **保留原文件**：不动原 `run-sccs-bench.mjs` 和原 `test1~test5.json`，Python 版
  全部新增在本 `qwenpaw/` 子目录

## 2. 架构差异（迁移核心）

| 维度 | OpenClaw（旧） | QwenPaw（新） |
| --- | --- | --- |
| 调用方式 | 每轮 `spawnSync("openclaw", ["agent","--json",...])` 子进程 | 常驻服务 `qwenpaw app`，HTTP SSE `POST /api/console/chat` |
| token 来源 | stdout JSON `result.meta.agentMeta.usage` | SSE `turn_usage` 事件 |
| 记忆位置 | OpenViking 实例 + `~/.openclaw/memory` | agent workspace 下的 ReMe 子目录 |
| 记忆检索工具 | OpenViking 插件 | 原生 `memory_search` |

> 关键：QwenPaw CLI `qwenpaw agents chat --json-output` **会主动丢弃**
> `turn_usage` 事件（见 `agent_management.py: collect_final_agent_chat_response`
> 与 `console.py:601`）。因此 **Python 脚本必须直连 HTTP SSE**，自己读全部
> SSE 行，才能拿到逐轮 token。

### 2.1 请求体结构（对齐 `build_agent_chat_request`）

`POST {base_url}/api/console/chat`，Header `X-Agent-Id: <agent>`，Body：

```json
{
  "session_id": "<会话id>",
  "user_id": "<agent>",
  "input": [{"role": "user", "content": [{"type": "text", "text": "<prompt>"}]}],
  "request_context": {"root_agent_id": "<agent>"}
}
```

### 2.2 SSE 事件解析

响应是 `text/event-stream`，每行 `data: {json}`：

- `type == "turn_usage"` → 取指标：
  ```json
  {"type":"turn_usage",
   "usage":{"prompt_tokens":N,"completion_tokens":N,"total_tokens":N,"estimated":bool},
   "context_usage":{"estimated_tokens":N,"max_input_length":N,"context_usage_ratio":F}}
  ```
- 最后一条 `type != "turn_usage"` 的事件 → 取回复文本：
  `output[-1].content[*].text`（对齐 `extract_agent_text_content`）。

## 3. 工具名映射（用例 prompt 必须同步改）

| OpenClaw 工具 | QwenPaw 函数 | policy_name | 源码位置 |
| --- | --- | --- | --- |
| `read` | `read_file` | `Read` | `agents/tools/file_io.py:106` |
| `exec` | `execute_shell_command` | `Bash` | `agents/tools/shell.py:505` |
| `rg` / grep | `grep_search` | `Grep` | `agents/tools/file_search.py:607` |
| glob | `glob_search` | `Glob` | `agents/tools/file_search.py:730` |
| （新增）AST | `ast_search` | `AstSearch` | `agents/tools/ast_tool.py:237` |
| 记忆检索 | `memory_search` | (ReMe) | `agents/memory/reme_light_memory_manager.py:380` |

- **本地文件读取能力：具备。** `read_file` 绝对路径原样使用、相对路径从
  workspace 解析（`_resolve_file_path`, file_io.py:52），支持 `start_line/end_line`；
  沙箱默认 `allow_read_all=True`（`sandbox/config.py:95`），可读 workspace 外仓库。
- 用例里原来的“只允许调用 4 次 read 工具 / 禁止 exec/rg”等措辞，要改成
  `read_file` / `execute_shell_command` / `grep_search`。

## 4. QwenPaw 原生记忆系统（ReMe Light）

- 默认后端 `memory_manager_backend="remelight"`（`config.py:1547`）。
- 记忆数据全部落在 **agent 自己的 workspace** 下（`ReMeLightMemoryConfig`,
  `config.py:669`）：

  | 子目录（默认名） | 用途 |
  | --- | --- |
  | `memory/` | daily 记忆笔记 |
  | `digest/` | digest 记忆 |
  | `mem_metadata/` | ReMe 持久状态 |
  | `mem_session/` | 自动记忆的源对话日志 |
  | `mem_agent/` | ReMe 内部 memory-agent 会话 |
  | `resource/` | 外部资源 |

- **用例间重置记忆 = 删除上述子目录**，与 OpenViking / `~/.openclaw/memory` 无关。
- **混合检索（向量+BM25）需配置 embedding**：在 `agent.json` 的
  `running.reme_light_memory_config.embedding_model_config` 填
  `backend / api_key / base_url / model_name / dimensions`（`config.py:609`）。
  未配置则自动退化为纯 BM25 关键词检索（`reme_config.py:648 _is_embedding_enabled`）。

## 5. 路径自适应策略

- 用例 JSON **只存 workspace 之后的相对路径**，如
  `kubernetes/pkg/kubelet/kubelet.go`。
- 脚本用环境变量 `BENCH_WORKSPACE_ROOT`（或 `--workspace-root`）解析根目录，
  运行时拼成绝对路径：`resolve_repo_path(rel) = Path(workspace_root)/rel`。
- 这样 Windows 编辑、Linux 部署都无需改 JSON。

## 6. 用例范围与改写

- 只用 **OpenViking / kubernetes / TypeScript** 三个仓库的样例。
- 去掉依赖 openclaw 仓库的原 test5，改写成 **TypeScript 仓库**的会话/编译链路用例。
- 全部改写为“QwenPaw agent + 原生记忆”语义，保留原多轮结构（ingest → 设计 → 交付）：
  - **ingest 轮**：`只允许调用 read_file，读取以下 workspace 相对路径…`
  - **记忆轮**：`只允许调用 memory_search，从原生记忆回取证据…`（验证工具结果
    压缩后仍能从原生记忆召回）

| 用例 | 仓库 | 主题 |
| --- | --- | --- |
| test1 | kubernetes | 多文件 read_file 摄取 → 无工具设计/交付 |
| test2 | kubernetes | kubelet Pod 处理链路 |

## 7. 交付物（全部新增于本目录 `qwenpaw/`）

1. **`run_sccs_bench.py`** — 核心 bench
   - `httpx` 流式 `POST /api/console/chat`，逐行解析 SSE，分离 `turn_usage` 与回复。
   - 每轮记录：`turn/turnId/prompt/status/durationMs/promptTokens/completionTokens/
     totalTokens/estimatedContextTokens/contextUsageRatio/replyChars/error`。
   - 汇总 p50/p90/totals/averages（翻自原 mjs 的 `percentile`/`computeSummary`/`toCsv`）；
     compaction 近似用 `context_usage_ratio` 跨阈值计数。
   - 输出 `--out-dir/<label>-<stamp>.json` + `.csv`。
   - `argparse` 子命令：`run`（`--prompts --label --session-id --timeout-sec
     --out-dir --base-url --agent --workspace-root`）、`compare`（`--baseline
     --candidate --out`）。
2. **`reset_memory.py`**（或 `run_sccs_bench.py --reset-memory`）
   - 定位 agent workspace（`<WORKING_DIR>/workspaces/<agent>` 或读 `agent.json`
     的 `workspace_dir`），删除记忆子目录（读 agent.json 覆盖默认名）。
   - 仅允许删除 WORKING_DIR 之内的目录（参照 `agents_cmd.py:
     _ensure_workspace_within_working_dir`）。
3. **`test1~test5.json`**（本目录内的 Python 版）— 相对路径 + QwenPaw 工具名 +
   原生记忆语义。
4. **`README.md`** — Python 版运行说明。

## 8. 端到端验证

1. 启动服务：`qwenpaw app --host 127.0.0.1 --port 8088 --log-level info`；
   `curl http://127.0.0.1:8088/api/version` 确认就绪。
2. `qwenpaw agents list` 拿到 `--agent` 的 id（默认 `default`）。
3. 设 `BENCH_WORKSPACE_ROOT` 指向含三个仓库的目录。
4. 跑单用例：
   ```bash
   python run_sccs_bench.py run --prompts test1.json --label test1 \
     --session-id "bench-$(date +%s)-qp-test1" --timeout-sec 600 \
     --out-dir bench-results/test1-qp --base-url http://127.0.0.1:8088 --agent default
   ```
   校验：退出码 0；每轮 `totalTokens>0`、`contextUsageRatio` 有值、ingest 轮 status 正常。
5. 记忆链路：ingest 后（reset 前）记忆轮确认 `memory_search` 能召回上轮证据；
   `reset_memory` 后再跑确认召回为空。
6. 用例间：每个用例前 reset，保证干净起点。
7. `compare` 子命令对比两份报告，确认指标 diff 输出正常。

## 9. 部署注意

- Linux 上启用混合检索需在 `agent.json` 配好可用 embedding provider；否则自动
  退化为纯 BM25（检索仍可用，但为关键词匹配）。
- `httpx` stream 的 `timeout` 要 ≥ `--timeout-sec`，避免长 ingest 轮过早断流。
